# α6500 实机 Movie 录像态候选缓冲抓取与分析（2026-09-02）

> 里程碑：首次通过 PMCA service shell 在 Movie 录像期间，用 `/dev/mem` 把 DMM
> 候选缓冲的真实物理内容 dump 到 SD 卡，再切回大容量存储用电脑读回并分析。

## 1. 执行链路

1. 相机开机，PMCA `serviceshell` 进入服务模式（`auth.stop()` 优雅退出）。
2. 在 BusyBox 相机 shell 里确认 `/dev/mem` 存在且可读（root）。
3. 用户切 Movie 模式开始录像；录像期间读 `/proc/udm/dmm_units` 抓候选类型。
4. 用 `dd if=/dev/mem of=/android/storage/sdcard0/xxx.BIN` 把候选缓冲前段写入 SD 卡
   （FUSE `FuFsys` 已就绪，短文件名为 8.3 格式）。
5. 每个候选地址抓 3 个时间点样本用于帧间对比。
6. 退出服务模式（`exit`），相机回到 normal/libusb 绑定的 `ILCE-6500` (PID 0AC4)。
7. 电脑侧用 `pnputil /remove-device` + `pnputil /delete-driver oem13x.inf` 把
   libusb 绑定移除，扫描后用原生 `USBSTOR` 驱动挂载 SD 卡为盘符 `F:`。
8. 复制全部 dump 到工作区，`tools/frame_compare.py`、`tools/stride_probe.py`、
   `tools/width_scan.py`、`tools/offset_width_scan.py` 分析。

## 2. 录像态 DMM 候选（与本机基线一致）

| unit type | 大小 | 物理地址 | 备注 |
| --- | --- | --- | --- |
| `0x321` | `0x02000000` (32MB) | `0x91000000` | 最大连续缓冲，RA 系列 |
| `0x311` | `0x00980000` (10MB) | `0x9d000000` | 池首，RB 系列 |
| `0x2d7` | `0x008dd800` (9.3MB) | `0xa4dbe000`、`0xa569b800` | RC 系列 |
| `0x8125b` | `0x00600000` (6MB) | `0x93080000` | RD 系列 |
| `0x2bd` | `0x00080000` (512KB) | `0x93000000` | RE 系列 |

注：录像态未出现 `0x236/0x1df/0x23e`（GetRawUnitTypeBase_Normal 的 RAW 主缓冲类型），
需要 Movie+DualRec / 特定 raw 输出配置，或这些类型仅在拍照 RAW 路径分配。

## 4. 分析结果

### 4.1 帧间变化（`frame_compare.py`，字节级 diff 比例）

| 候选 | 1↔2 | 2↔3 | 变化集中区域 | 判读 |
| --- | --- | --- | --- | --- |
| RA | 0.996 | 0.996 | 均匀 | 几乎全部字节每帧都变，活跃但无结构 |
| RB | 0.996 | 0.996 | 均匀 | 同上 |
| RC | 0.536 | 0.531 | 均匀 | 约一半变，有结构 |
| RD | 0.009 | 0.010 | 仅首 128KB | 基本静态 |
| RE | — | — | — | 未做三帧 |

### 4.2 零字节占比（关键鉴别）

| 候选 | 8-bit 零占比 | u16 低字节零 | u16 高字节零 |
| --- | --- | --- | --- |
| RC1 | **0.456** | 0.464 | 0.448 |
| RA1 | 0.004 | 0.004 | 0.004 |
| RB1 | 0.012 | 0.013 | 0.010 |
| RD1 | 0.042 | 0.038 | 0.047 |
| RE1 | 0.181 | 0.358 | 0.005 |

### 4.3 行宽/位深扫描

- `offset_width_scan.py` 8-bit：RC1 最佳 cost=54.09（随机基线≈85），但 RC1 高零占比
  说明低 cost 是零长串的假象。
- `width_scan.py` 8-bit 与 16-bit、`render_best.py`（8/10/12/16-bit × 多种行宽）：
  - RA1 在所有位深下，行内成本均≈随机基线（8-bit≈85，10-bit≈341=1023/3），
    无 2D 图像结构，**否定 RA1 为简单像素帧缓冲**。
  - RB1 同 RA1，无结构。
- RC1 字节自相关：lag 64 差值最小（43.93，低于 lag 1 的 55）。
  64 字节块列均值显示前 24 列高方差（std≈70），24-31 列是 0→88 平滑渐变，
  判读为**结构化描述符/填充元数据，而非 Bayer 像素帧**。
- RA1/RB1/RC1 渲染（8-bit 3840 / 10-bit / 12-bit / 16-bit 多行宽）目视均为
  竖条纹或噪声，**未出现干净图像**。

### 4.4 RC 64 字节块内部结构（帧间稳定性）

逐字节列变化率（RC1 vs RC2）：字节 [6:7] 变化率 = 0.00（帧间恒定），
字节 [0:6] 与 [8:32] 变化率 ≈ 0.98（高度变化 payload），字节 [32:63]
变化率从 0.00 渐升至 0.93（递增，疑似序号/帧计数/偏移字段）。

结论：RC 块是**带固定 magic（`fc ff`）+ 动态 payload + 递增序号字段的
流/描述符结构**，不是像素帧缓冲。

## 5. 证据分级结论

| 结论 | 等级 | 证据 |
| --- | --- | --- |
| 录像期间 DMM 出现 0x321/0x311/0x2d7/0x8125b/0x2bd 常驻大缓冲 | 已证实 | dmm_units 实测 |
| `/dev/mem` 可在录像期间只读 dump 物理 DRAM 到 SD 卡并取回 | 已证实 | 全链路成功，MD5 一致 |
| 电脑可用 pnputil 移除 libusb 绑定、切原生 usbstor 读 SD 卡 | 已证实 | remove-device + delete-driver + scan |
| RA/RB/RC 这批候选缓冲在 8/10/12/16-bit 常见行宽下**不是干净像素帧** | 否定（这些候选/解释） | 行内成本=随机；目视噪声/条纹 |
| RA/RB 是无结构活跃缓冲（疑似流/压缩中间数据） | 高可信推测 | 帧间 99.6% 变化、0% 结构 |
| RC 是带固定 magic(`fc ff`)+递增序号字段的流/描述符缓冲 | 高可信推测 | 块字节 [6:7] 帧间恒定；[32:63] 递增；docs/17 §4.4 |
| 已抓到 Bayer 像素帧 | 否定（当前抓取/解释） | 未出现可识别 Bayer 图像 |

## 6. 下一步建议

1. **重新确认抓取窗口**：当前每种候选只抓了前 2MB。若真帧缓冲更大或行宽 >6144，
   需抓完整缓冲（如 RA 32MB）并限制在帧起始位置。
2. **换拍照/DualRec 路径**：可读回 `0x236/0x1df/0x23e` 是否出现；拍照 RAW 很可能
   走更干净的 RAW 缓冲。
3. **用 stream2 ioctl/mmap**（docs/13）做受控物理映射，配合完整帧大小验证。
4. **对比同场景静止画面**：静止时帧间变化应大幅下降；当前 RA/RB 99.6% 变化
   说明可能是流缓冲，静止场景下应能区分。

> 关键判断：本次分到的 0x321/0x311/0x2d7/0x8125b/0x2bd 属于**视频管线缓冲**
> （可能是 YUV、处理中间态、流数据或描述符），但这些具体类型仍未证实；未见 0x236/0x1df/0x23e（GetRawUnitTypeBase_Normal
> 的 RAW 主缓冲类型）。要拿 RAW，需触发该类型分配路径（Movie+DualRec 或特定
> raw 输出配置），或从 stream2/DFE 通道取。**下一步以触发 RAW 单元分配为主**。
